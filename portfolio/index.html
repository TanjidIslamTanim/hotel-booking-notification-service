01 / OVERVIEW

What this project
sets out to solve.

A Spring Boot service that consumes booking events, creates confirmation or cancellation notification records, persists them through JPA and exposes notification data via REST.

01

The challenge

Booking and notification processing are different responsibilities. Event-driven messaging lets a dedicated service respond to booking updates.

02

The approach

A Spring Boot service that consumes booking events, creates confirmation or cancellation notification records, persists them through JPA and exposes notification data via REST.

02 / CAPABILITIES

real workflows.

01 / FEATURE

Kafka listener

Consumes booking-events using Spring Kafka.

02 / FEATURE

Booking confirmations

Creates BOOKING_CONFIRMED notification records.

03 / FEATURE

Cancellations

Handles BOOKING_CANCELLED events and records the outcome.

04 / FEATURE

Data persistence

Stores notifications using Spring Data JPA and H2.

05 / FEATURE

REST API

Create, list, retrieve and delete notification records.

06 / FEATURE

Layered design

Separate controller, service, repository, entity and event packages.
